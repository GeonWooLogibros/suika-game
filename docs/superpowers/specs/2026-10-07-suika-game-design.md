# 수박게임 설계 문서

작성일: 2026-10-07

## 1. 목적

브라우저에서 실행하는 수박게임입니다. 과일을 통에 떨어뜨려 같은 과일끼리 합치고, 가장 큰 과일인 수박을 만드는 원작 규칙을 그대로 따릅니다. 혼자서 최고 점수에 도전할 수 있고, 방을 만들어 친구와 같이 하면서 누가 먼저 수박을 만드는지 겨룰 수 있습니다.

재미를 위한 개인 프로젝트이며, 완성한 뒤에는 claude.ai 아티팩트와 공개 사이트 두 곳에 올려서 다른 사람과 같이 합니다.

### 성공 기준

- `npm run dev`로 실행한 뒤 처음 화면에서 혼자 하기를 골라 한 판을 끝까지 진행할 수 있습니다.
- 과일이 쌓이고 구르고 합쳐지는 움직임이 원작과 비슷하게 느껴지며, 쌓인 과일이 눈에 띄게 떨리거나 서로 겹치지 않습니다.
- 터치, 마우스, 키보드 가운데 어느 것으로도 과일을 떨어뜨릴 수 있습니다.
- 브라우저 탭 두 개로 방 만들기, 초대 링크로 들어가기, 준비, 시작, 승리 판정, 다시 하기까지 진행할 수 있습니다.
- 같이 하는 동안 상대의 통과 점수가 내 화면에 실시간으로 보입니다.
- 최고 점수가 브라우저를 다시 열어도 유지됩니다.
- `npm test`와 `npm run build`가 오류 없이 통과합니다.

### 범위에서 제외하는 것

- 상대를 방해하는 요소(방해 구슬, 아이템)와 특수 과일
- 한 통을 여러 사람이 함께 쓰는 방식
- 컴퓨터 상대
- 배경 음악
- 이미지 파일과 음원 파일(모든 그림과 소리는 코드로 생성합니다)
- 두 곳에 실제로 올리는 작업(로컬에서 완성본을 확인한 뒤 따로 진행합니다)

## 2. 기술 구성

- Vite + TypeScript + Vitest를 사용하며, 형제 프로젝트인 `retro-racer`와 같은 구성을 따릅니다.
- UI 프레임워크는 사용하지 않습니다. 통과 과일, 점수 표시, 화면 전환을 모두 Canvas 2D에 직접 그립니다. 이름과 방 코드를 입력하는 칸만 HTML 입력 요소를 캔버스 위에 겹쳐서 씁니다.
- 실행 의존성은 `matter-js`(물리)와 `peerjs`(공개 사이트의 같이 하기) 두 개입니다. `peerjs`는 공개 사이트용 빌드에서만 불러오므로 아티팩트용 빌드에는 포함되지 않습니다.
- 저장소 위치는 `game-projects/suika-game/`이며 독립된 git 저장소로 관리합니다.

### 물리 엔진을 matter-js로 정한 이유

이 게임의 재미는 과일이 쌓이고 굴러가는 손맛에 크게 좌우됩니다. matter-js는 원이 쌓였을 때의 안정성이 검증되어 있어서 원작과 비슷한 손맛에 빨리 도달할 수 있습니다. 원 전용 물리를 직접 작성하는 방법도 검토했지만, 쌓인 과일의 떨림과 겹침을 조정하는 데 시간이 많이 들고 손맛이 어색해질 위험이 큽니다. 같이 하기가 점수 경쟁형이라서 여러 사람의 물리 결과를 똑같이 맞출 필요가 없으므로, 직접 작성한 물리가 주는 이점도 없습니다.

## 3. 게임 규칙

### 과일

과일은 11단계입니다. 떨어뜨릴 과일은 앞의 5단계 가운데에서 나옵니다.

| 단계 | 과일 | 합쳐서 만들었을 때 점수 |
|---|---|---|
| 1 | 체리 | 떨어뜨릴 때만 나옵니다 |
| 2 | 딸기 | 1 |
| 3 | 포도 | 3 |
| 4 | 한라봉 | 6 |
| 5 | 감 | 10 |
| 6 | 사과 | 15 |
| 7 | 배 | 21 |
| 8 | 복숭아 | 28 |
| 9 | 파인애플 | 36 |
| 10 | 멜론 | 45 |
| 11 | 수박 | 55 |

- 수박 둘이 합쳐지면 둘 다 사라지고 66점을 얻습니다.
- 과일의 반지름은 단계가 올라갈수록 커지며, 통의 너비를 기준으로 한 비율로 정합니다. 수박의 지름은 통 너비의 절반에 가깝게 맞춥니다. 구체적인 값은 구현하면서 손맛을 보고 조정합니다.

### 진행

- 통 위에서 좌우로 위치를 잡고 과일을 놓습니다. 과일은 통의 벽 안쪽에서만 놓을 수 있습니다.
- 과일을 놓고 약 0.5초가 지나면 다음 과일이 나옵니다. 다음에 나올 과일 하나를 미리 보여 줍니다.
- 같은 단계의 과일 둘이 닿으면 두 과일의 중간 지점에 다음 단계의 과일 하나가 생깁니다. 한 번의 물리 진행에서 과일 하나는 한 번만 합쳐집니다.
- 과일이 선 위에 약 2초 이상 머물면 판이 끝납니다. 방금 놓은 과일은 통 안의 다른 물체에 닿기 전까지 이 판정에서 제외합니다.
- 과일의 순서는 시드로 정하는 난수로 결정합니다. 같은 시드에서는 항상 같은 순서가 나옵니다.

### 조작

| 입력 | 동작 |
|---|---|
| 터치·마우스로 끌기 | 위치 잡기 |
| 손가락을 떼기, 마우스 버튼을 놓기 | 과일 떨어뜨리기 |
| ← / → (또는 A / D) | 위치 잡기 |
| Space (또는 ↓) | 과일 떨어뜨리기 |

## 4. 같이 하기

### 흐름

1. 한 사람이 방을 만들면 다섯 글자 방 코드와 초대 링크(`주소#방코드`)가 생깁니다.
2. 다른 사람은 초대 링크를 열거나 방 코드를 입력해서 대기실에 들어옵니다. 한 방에는 최대 4명이 들어올 수 있습니다.
3. 방장이 아닌 사람은 준비하기를 누릅니다. 모두 준비하면 방장이 시작할 수 있습니다.
4. 방장이 시작하면 3초 동안 숫자를 센 뒤 모두 동시에 시작합니다. 과일 순서를 정하는 시드는 방장이 정하며 모두 같은 값을 씁니다.
5. 판이 끝나면 결과 화면에 순위를 보여 주고, 방장이 다시 하기를 누르면 대기실로 돌아갑니다.

### 승패

- 수박을 가장 먼저 만든 사람이 즉시 이기고 판이 끝납니다.
- 두 사람 이상이 거의 동시에 수박을 만들었다면, 각자가 판이 시작된 뒤 수박을 만들기까지 걸린 시간을 비교해서 더 짧은 사람이 이깁니다. 이 시간은 각자의 화면에서 센 물리 진행 횟수로 계산하므로 기기 사이의 시계 차이에 영향을 받지 않습니다.
- 선을 넘은 사람은 탈락하고 남은 사람의 통을 구경합니다.
- 한 사람만 남아도 판은 계속됩니다. 남은 사람이 수박을 만들거나 선을 넘으면 판이 끝납니다.
- 아무도 수박을 만들지 못하고 모두 탈락하면 점수가 높은 순서로 순위를 매깁니다.
- 순위는 수박을 만든 사람, 점수가 높은 사람 순서로 정합니다.

### 사람이 나가거나 연결이 끊겼을 때

- 판 도중에 나간 사람은 탈락한 것으로 처리하고, 나가기 직전의 점수로 순위에 넣습니다.
- 방장이 나가면 방에 가장 먼저 들어온 사람이 방장이 됩니다.
- 상대의 상태가 3초 동안 오지 않으면 그 사람의 통에 연결이 불안정하다고 표시하고, 10초 동안 오지 않으면 나간 것으로 처리합니다.

### 주고받는 값

각 사람은 자기 상태를 방의 presence에 올리고, 다른 사람의 presence를 읽습니다.

| 값 | 설명 |
|---|---|
| 이름 | 최대 12자 |
| 방장 여부, 들어온 시각 | 방장을 정하는 데 씁니다 |
| 단계 | 대기실, 숫자 세는 중, 판 진행 중 |
| 준비 여부 | 대기실에서만 씁니다 |
| 판 이름, 시드 | 방장의 값만 씁니다. 판을 시작할 때마다 방장이 새로 정합니다. 각자 방장의 새 판 이름을 본 순간부터 3초를 셉니다 |
| 점수, 가장 큰 과일 단계 | |
| 판 안에서의 상태 | 진행 중, 탈락, 수박 완성 |
| 수박을 만들기까지 걸린 시간 | 수박을 만들었을 때만 넣습니다 |
| 통 요약 | 통 안의 과일마다 x, y, 단계를 정수로 줄여서 이어 붙인 문자열 |

- 통 요약은 초당 약 8회 보냅니다. 과일 하나에 6자를 쓰므로 과일이 60개일 때 약 360자입니다.
- 받는 쪽은 직전 요약과 새 요약 사이를 보간해서 상대의 통을 작게 그립니다. 과일의 회전은 보내지 않습니다.
- 다른 사람에게서 받은 값은 화면에 쓰기 전에 형식, 길이, 범위를 검사합니다. 검사를 통과하지 못한 값은 버리고 직전 값을 계속 씁니다.

### 연결 방식

Retro Racer의 `src/net/`에 있는 방 인터페이스(`RoomLike`, `LobbyLike`)와 어댑터를 복사해서 씁니다.

- claude.ai 아티팩트 안에서 열었을 때는 `room` 기능을 씁니다.
- 공개 사이트용 빌드(`VITE_NET=p2p`)에서는 PeerJS의 공개 시그널링 서버를 거치는 P2P 연결을 씁니다.
- 둘 다 아니거나 연결에 실패하면 혼자 하기만 보여 주고, 같이 하기를 쓸 수 없는 이유를 안내합니다. 연결을 시도한 지 10초가 지나면 실패로 봅니다.
- Retro Racer에 있는 Supabase 어댑터는 가져오지 않습니다.

## 5. 화면

세로로 긴 화면을 기준으로 배치하고, 가로로 넓은 화면에서는 남는 양옆 공간을 씁니다.

| 화면 | 내용 |
|---|---|
| 처음 화면 | 제목, 최고 점수, 혼자 하기, 방 만들기, 코드로 들어가기, 이름 입력 |
| 대기실 | 방 코드, 초대 링크 복사하기, 들어온 사람과 준비 상태, 준비하기 또는 시작하기, 나가기 |
| 게임 | 가운데에 내 통, 위쪽에 점수·최고 점수·다음 과일, 과일이 커지는 순서 안내, 상대의 통 최대 3개(이름, 점수, 가장 큰 과일) |
| 결과 | 혼자 하기에서는 점수와 최고 점수, 같이 하기에서는 순위표. 다시 하기와 처음으로 가기 |

- 상대의 통은 넓은 화면에서는 내 통의 옆에, 좁은 화면에서는 내 통의 위쪽에 한 줄로 놓습니다.
- 과일은 단계마다 색이 다른 원에 간단한 얼굴과 꼭지를 그려서 표현합니다.
- 과일이 합쳐질 때 새 과일이 잠깐 커졌다가 돌아오고, 작은 조각이 흩어지며, 얻은 점수가 떠오릅니다.
- 효과음은 Web Audio로 합성합니다. 과일을 놓을 때, 합쳐질 때(단계가 높을수록 낮은 소리), 판이 끝날 때, 수박을 만들었을 때 소리를 냅니다. 소리를 끄는 버튼을 둡니다.
- 문구는 버튼에 "~하기"나 명사형을 쓰고, 안내와 설명에는 "~합니다" 형태를 씁니다.

## 6. 코드 구조

```
src/
  game/            순수 규칙. matter-js와 DOM을 사용하지 않습니다.
    fruits.ts      단계별 이름, 반지름, 점수, 색
    random.ts      시드 난수와 과일 순서
    rules.ts       합치기 결과, 점수, 선 넘음 판정
    match.ts       방 상태 읽기, 방장 정하기, 승자와 순위 계산, 방 코드
    snapshot.ts    통 요약의 인코딩, 디코딩, 검사, 보간
  physics/
    world.ts       matter-js를 감싼 층. 과일 추가와 제거, 한 걸음 진행, 맞닿은 과일 쌍 알림
  session.ts       한 판의 진행. 물리와 규칙을 묶어서 화면에 그릴 상태를 만듭니다.
  net/             Retro Racer에서 복사한 방 인터페이스와 어댑터
    types.ts  connect.ts  p2p-room.ts
  multiplayer.ts   대기실과 대전의 상태 기계
  render/          Canvas 그리기
    layout.ts  bin.ts  fruit.ts  rivals.ts  hud.ts  screens.ts  effects.ts
  input.ts         터치, 마우스, 키보드 입력
  audio.ts         효과음 합성
  storage.ts       최고 점수와 이름 저장
  main.ts          시작점과 화면 전환
```

### 모듈 사이의 경계

- `game/`은 다른 폴더를 불러오지 않습니다. 입력과 출력이 값뿐인 함수로 구성하므로 단위 테스트의 주 대상이 됩니다.
- `physics/world.ts`만 matter-js를 불러옵니다. 바깥에는 과일의 위치·단계 목록과 맞닿은 쌍만 내보내므로, 물리 엔진을 바꾸더라도 이 파일만 고치면 됩니다.
- `session.ts`는 물리를 고정 간격(1/60초)으로 진행합니다. 화면 주사율이 다른 기기에서도 과일이 같은 속도로 움직입니다. 한 프레임에 진행할 수 있는 횟수에 상한을 두어, 탭이 오래 숨겨졌다가 돌아왔을 때 한꺼번에 많이 진행되지 않게 합니다.
- `multiplayer.ts`는 `net/`의 방 인터페이스에만 의존하고, 연결 방식이 무엇인지 알지 못합니다.
- `render/`는 상태를 읽어서 그리기만 하고 상태를 바꾸지 않습니다.

### 저장

localStorage에 다음 두 키만 씁니다. 다른 게임이 같은 주소의 저장 공간을 함께 쓸 수 있으므로, 이 두 키 외에는 읽거나 지우지 않습니다.

- `suika-game.best.v1`: 혼자 하기의 최고 점수
- `suika-game.name.v1`: 같이 하기에서 쓰는 이름

저장 공간을 쓸 수 없는 환경에서도 게임이 동작해야 하므로, 읽기와 쓰기에서 발생하는 오류는 무시하고 기본값을 씁니다.

## 7. 테스트

### 단위 테스트

- 과일 순서: 같은 시드에서 같은 순서가 나오고, 앞의 5단계만 나옵니다.
- 합치기와 점수: 단계별 결과와 점수가 표와 일치하고, 수박 둘이 합쳐지면 둘 다 사라집니다.
- 선 넘음 판정: 선 위에 머문 시간이 기준을 넘을 때만 끝나고, 선 아래로 내려가면 시간이 초기화되며, 방금 놓은 과일은 제외합니다.
- 통 요약: 인코딩한 뒤 디코딩하면 원래 값이 나오고, 형식이 잘못되었거나 너무 긴 값은 거부합니다. 과일의 수가 달라진 두 요약 사이의 보간도 확인합니다.
- 승자와 순위: 수박을 한 사람이 만든 경우, 두 사람이 만든 경우, 모두 탈락한 경우, 도중에 나간 사람이 있는 경우를 확인합니다.
- 방장 정하기: 방을 만든 사람이 있을 때와 나갔을 때를 확인합니다.
- 방 코드: 만들기와 초대 링크에서 꺼내기를 확인합니다.

### 물리 통합 테스트

- 같은 단계의 과일 둘을 같은 자리에 차례로 떨어뜨리면 다음 단계의 과일 하나로 합쳐집니다.
- 과일을 여러 개 떨어뜨리고 충분히 진행해도 과일이 통 밖으로 나가지 않습니다.
- 과일을 선 위까지 쌓으면 판이 끝납니다.

### 브라우저에서 직접 확인

- 혼자 하기 한 판을 터치(또는 마우스)와 키보드로 각각 진행합니다.
- 탭 두 개로 같이 하기를 진행하며 대기실, 시작, 상대 통 표시, 탈락, 승리 판정, 다시 하기를 확인합니다.
- 좁은 화면과 넓은 화면에서 배치가 깨지지 않는지 확인합니다.

수박을 실제로 만들어서 승리 판정을 확인하려면 시간이 오래 걸리므로, 개발 중에만 쓸 수 있는 방법(예: 주소에 붙이는 값으로 떨어뜨릴 과일의 단계를 높이는 기능)을 두고 배포용 빌드에서는 동작하지 않게 합니다.

## 8. 배포

이번 구현의 범위는 로컬에서 완성하고 탭 두 개로 확인하는 것까지입니다. 배포는 완성본을 확인한 뒤에 진행하며, 그때 필요한 구성은 다음과 같이 미리 맞춰 둡니다.

- `npm run build`: 아티팩트용입니다. 결과물인 스크립트 파일 하나를 HTML 한 장에 넣어서 `room` 기능과 함께 올립니다.
- `npm run build:web`: 공개 사이트용입니다. `.env.web`에 `VITE_NET=p2p`를 두고 `dist-web`에 빌드합니다.
- Vite의 `base`는 `./`로 두어 GitHub Pages의 하위 경로에서도 파일을 찾을 수 있게 합니다.

## 9. 확인이 필요한 위험

- **presence 크기 제한**: claude.ai `room` 기능의 presence에 올릴 수 있는 값의 크기에 제한이 있는지 확인하지 못했습니다. 구현 초기에 먼저 확인하고, 제한에 걸리면 보내는 주기를 늘리거나 좌표의 정밀도를 낮춥니다.
- **물리 손맛**: 반발, 마찰, 과일의 무게 같은 값은 실제로 해 보면서 조정해야 합니다. 조정할 값은 `physics/world.ts`의 상수로 모아 둡니다.
- **숨겨진 탭**: 탭이 숨겨지면 화면 갱신이 멈추므로 그 사람의 판도 멈춥니다. 같이 하기에서 이 상태가 10초 이상 이어지면 다른 사람에게는 나간 것으로 보입니다. 이번 범위에서는 이 동작을 그대로 둡니다.
